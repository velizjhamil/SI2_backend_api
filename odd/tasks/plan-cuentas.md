# Feature: plan-cuentas (CU-W29 Configuración y Control del Plan de Cuentas)

## Objective
Chart of accounts aligned with the Bolivian regulator: the official ASFI "Manual de Cuentas para Entidades
Financieras" (MCEF), Título II Nomenclatura, plus per-cooperative analytic accounts. Base for W30 (comprobantes),
W31 (libros), W32 (estados financieros).

## Source (verified by the orchestrator against the primary PDF)
- https://servdmzw.asfi.gob.bo/circular/Manual/T02.pdf (ModDate 2026-09-11). Local copy + text:
  `/home/yimy/proyectos/si2/investigacion/T02.pdf`, `T02.txt` (pdftotext -layout), `mcef_t02.csv` (first-pass parse,
  1997 rows; some names are truncated where the PDF wraps a line — the migration generator must join continuation lines).
- Code format `NNN.NN`: class `X00.00` (nivel 1), grupo `XX0.00` (nivel 2), cuenta `XXX.00` (nivel 3),
  subcuenta `XXX.NN` with NN != 00 (nivel 4).
- Classes: 100 ACTIVO, 200 PASIVO, 300 PATRIMONIO, 400 GASTOS, 500 INGRESOS, 600 CONTINGENTES DEUDORAS,
  700 CONTINGENTES ACREEDORAS, 800 ORDEN DEUDORAS, 900 ORDEN ACREEDORAS.
  WARNING: the SIN tax nomenclature uses 4=Ingresos/5=Gastos. That is NOT the MCEF. Use MCEF.
- Natural balance: 1xx, 4xx, 6xx, 8xx DEUDORA; 2xx, 3xx, 5xx, 7xx, 9xx ACREEDORA.
  Regularizing (contra) accounts are printed in parentheses in the manual, e.g. `139.00 (PREVISIÓN PARA INCOBRABILIDAD
  DE CARTERA)`: they take the opposite nature of their class and `es_regularizadora = true` (strip the parentheses from
  `nombre`).

## Current state
- `plan_cuenta(id, codigo UNIQUE, nombre, nivel, tipo, plan_cuenta_padre_id)` with 5 legacy rows using codes like
  `100-000`, `111-001`, `131-001`. `detalle_asiento` has 3 rows referencing legacy ids 3 (111-001) and 5 (131-001).
- No backend code uses these tables yet. Roles: CONTADOR, ADMINISTRADOR exist (contador@test.com).

## Design
### Migration `024_sprint11_plan_cuentas.sql` (idempotent, runs on Supabase too)
- `plan_cuenta` new columns: `naturaleza VARCHAR(10) CHECK IN ('DEUDORA','ACREEDORA')`, `es_regularizadora BOOL
  DEFAULT false`, `es_oficial BOOL DEFAULT false`, `cooperativa_id INT NULL REFERENCES cooperativa(id)` (NULL = official
  shared catalog), `estado VARCHAR(10) DEFAULT 'ACTIVA' CHECK IN ('ACTIVA','INACTIVA')`, `acepta_movimientos BOOL`,
  `descripcion TEXT NULL`, `fecha_creacion TIMESTAMP DEFAULT now()`.
- Replace the global UNIQUE on `codigo` with a unique index on `(COALESCE(cooperativa_id, 0), codigo)`.
- Seed the full official MCEF catalog (levels 1–4) with `es_oficial = true`, `cooperativa_id NULL`, correct parents,
  `naturaleza`, `es_regularizadora`; `acepta_movimientos = true` only for nivel 4 (subcuentas). Upsert by codigo.
  Generate the INSERTs from T02.txt with a script (commit the script under `scripts/`), not by hand.
- Legacy rows: remap `detalle_asiento.plan_cuenta_id` 111-001 → `111.01`, 131-001 → `131.05`, 100-000 → `100.00`,
  110-000 → `110.00`, 130-000 → `130.00`; then delete the 5 legacy rows. Idempotent on replay.
- `tipo` column: keep, fill with the class name (ACTIVO, PASIVO, ...) for compatibility.

### Analytic accounts (nivel 5, per cooperative)
- Code = parent subcuenta code + `.` + 2-digit correlative per (cooperativa, parent): e.g. `111.01.01`, `111.01.02`.
  Generated by the server, never sent by the client.
- Parent must be an official nivel-4 account (ACTIVA). Nature and regularizing flag are inherited from the parent.
- Once a subcuenta has analytic accounts in a cooperative, postings in that cooperative must use the analytic
  accounts (W30 will enforce it; expose `tiene_analiticas` in the API).
- Official accounts are immutable (no edit/delete/deactivate through the API).

### API (prefix `/api/v1/contabilidad`, roles: read CONTADOR, ADMINISTRADOR; write CONTADOR, ADMINISTRADOR;
tenant = the user's cooperative; other tenants' analytic accounts are invisible → 404)
- `GET /plan-cuentas?clase=1..9&nivel=1..5&q=&estado=ACTIVA|INACTIVA&solo_movimiento=bool` → flat list ordered by
  codigo: `{id, codigo, nombre, nivel, naturaleza, es_regularizadora, es_oficial, estado, acepta_movimientos,
  padre_id, padre_codigo, tiene_analiticas}`. `q` matches codigo prefix or name (accent-insensitive if easy).
- `GET /plan-cuentas/arbol?clase=` → nested tree `{..., hijos: [...]}` for one class (required param, 422 if missing),
  to keep the payload small.
- `GET /plan-cuentas/{id}` → detail + ancestors path `[{codigo, nombre}]` + `movimientos: int` (count of
  detalle_asiento rows in this cooperative; 0 today).
- `POST /plan-cuentas` `{padre_id, nombre, descripcion?}` → 201 analytic account. 422 if parent is not official
  nivel 4 or not ACTIVA; 422 blank name; 409 duplicate name under same parent in same cooperative.
- `PATCH /plan-cuentas/{id}` `{nombre?, descripcion?}` → analytic of own cooperative only; official → 403
  "Las cuentas oficiales ASFI no se pueden modificar".
- `POST /plan-cuentas/{id}/estado` `{estado, motivo}` (motivo required, min 5 chars) → analytic only; deactivation
  blocked with 409 if the account balance (sum debe − haber in this cooperative) is not zero.
- `DELETE /plan-cuentas/{id}` → analytic only and only with 0 movements (else 409, suggest deactivating).
- Every write logs `registrar_accion` (modulo CONTABILIDAD).
- `GET /plan-cuentas/resumen` → counts per class and level (official + own analytic), for the header cards.
