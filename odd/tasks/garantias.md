# Feature: Guarantees, collateral and guarantors (CU-W22)

Route: W25 ✅ → W28 ✅ → **W22** → W18. Autonomous run authorized by the user (2026-09-27).

## User story (fictional, drafted by the orchestrator)
**CU-W22 Gestión de Garantías, Bienes y Avales** — Actors: Oficial de crédito (registers), Administrador (verifies).
> Como oficial de crédito quiero registrar las garantías de una solicitud (hipotecas, prendas y avales personales) con su valuación, y que un administrador las verifique, para que los productos que exigen garantía solo avancen con cobertura suficiente y las garantías se liberen al cancelar el crédito.

Acceptance criteria:
1. Register guarantees on a request while it is PENDIENTE or OBSERVADA: HIPOTECARIA (property), PRENDARIA (vehicle/machinery/movable asset) and PERSONAL (guarantor/aval).
2. Collateral valuation: commercial value and realizable value computed with a haircut per type; guarantor data includes identity, monthly income and relationship.
3. Maker–checker: an administrator verifies or rejects each guarantee with an observation; only VERIFICADA guarantees count for coverage.
4. Coverage = Σ realizable value of verified guarantees / requested amount. For products that require a guarantee, the CU-W23 evaluation adds a knock-out when coverage is below the product minimum (manual review → committee, CU-W25).
5. When a credit is fully paid (CANCELADO, CU-W27) its guarantees become LIBERADA automatically. Everything is audited.

## Decisions (orchestrator)
- Types and realizable-value factors (constants): HIPOTECARIA 0.70; PRENDARIA 0.50; PERSONAL: realizable value = min(guarantor monthly income × 12 × 0.30, requested amount) — a guarantor's capacity proxy.
- Guarantee currency must match the request currency (400 otherwise); PERSONAL uses the request currency.
- `producto_credito.cobertura_minima_garantia NUMERIC(6,2) NOT NULL DEFAULT 100.00` (%). Demo values: MICRO-BOB 100, VIV-USD 125, CONS-BOB 0 (not required). Editable via the CU-W20 product endpoints/UI (additive field).
- States: REGISTRADA → VERIFICADA | RECHAZADA; VERIFICADA → LIBERADA (on credit CANCELADO). Edit/delete only while REGISTRADA and the request is PENDIENTE/OBSERVADA.
- Guarantor (PERSONAL) cannot be the request's own socio (400); optional `socio_avalista_id` when the guarantor is a member of the same cooperative.
- Scoring engine: new knock-out `GARANTIA_INSUFICIENTE` → REVISION_MANUAL, applied only when the product `requiere_garantia`. Engine version becomes `reglas-v2`; factor weights and every other rule unchanged (existing W23 tests must keep passing; tests asserting the version string may be updated). The model (mora-logit-v1) is untouched.
- Roles: register/edit/delete = OFICIAL_CREDITO or ADMINISTRADOR; verify/reject = ADMINISTRADOR (cannot verify a guarantee they registered — 403); read = cooperative staff.
- Bitácora `CREDITOS`: `REGISTRAR_GARANTIA`, `ACTUALIZAR_GARANTIA`, `ELIMINAR_GARANTIA`, `VERIFICAR_GARANTIA`, `LIBERAR_GARANTIA`.
- Also fix two CU-W28 follow-ups here: (a) `/creditos/monitoreo/resumen` amounts as 2-decimal strings like the rest of the API; (b) validation `detail` messages must not include the Pydantic prefix "Value error, " (strip it in the 400 handler used by alerts).

## API contract (backend and frontend MUST follow exactly)
Base `/api/v1/creditos`. Errors `{"detail": "..."}`. Amounts as 2-decimal strings.

`GarantiaOut` = `{id, tipo, descripcion, moneda, valor_comercial | null, valor_realizable, documento_referencia | null, avalista: {nombre, ci, ingreso_mensual, relacion, telefono, socio_id | null} | null, estado, observacion_verificacion | null, usuario_registro: {id, nombre}, usuario_verificacion: {id, nombre} | null, fecha_registro, fecha_verificacion | null, fecha_liberacion | null}`.
`CoberturaOut` = `{requiere_garantia, cobertura_minima, monto_solicitado, valor_realizable_verificado, valor_realizable_pendiente, porcentaje_cobertura, cumple}` (`cumple` true when not required).

1. `POST /creditos/solicitudes/{id}/garantias` body HIPOTECARIA/PRENDARIA `{tipo, descripcion, moneda_id, valor_comercial, documento_referencia?}`; PERSONAL `{tipo, descripcion, avalista: {nombre, ci, ingreso_mensual, relacion, telefono?, socio_id?}}` → `201 GarantiaOut`. 400 invalid data / currency mismatch / guarantor is the borrower; 409 request not PENDIENTE/OBSERVADA.
2. `GET /creditos/solicitudes/{id}/garantias` → `[GarantiaOut]`.
3. `PUT /creditos/garantias/{id}` (partial, same fields except `tipo`) → `GarantiaOut`; 409 if not REGISTRADA or request not editable.
4. `DELETE /creditos/garantias/{id}` → `204`; same 409 rules.
5. `POST /creditos/garantias/{id}/verificacion` body `{decision: "VERIFICADA"|"RECHAZADA", observacion (≥ 5 chars)}` → `GarantiaOut`. 403 non-admin or same user who registered it; 409 not REGISTRADA.
6. `GET /creditos/solicitudes/{id}/cobertura` → `CoberturaOut`.
7. `GET /creditos/creditos/{id}/garantias` → `[GarantiaOut]` of the credit's request.
8. Additive: `ProductoCreditoOut` + `cobertura_minima_garantia` (writable in CU-W20 POST/PUT); `SolicitudOut` + `cobertura: CoberturaOut | null`.
